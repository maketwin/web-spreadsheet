# Excel 运行时模拟与接口接管平台（Mock Platform）设计

> 2026-10-20 · 合并自两轮设计讨论（平台主体 + 操作记录子系统），并标注 M1 实现状态。
> M1 原型代码：`src/platform/`，演示页：`platform.html`（`pnpm dev` 后访问）。

## 1. 定位

一个把「工作簿逻辑」和「外部接口」解耦的平台：

- **左边是 Excel 模拟运行时**：打开工作簿、算公式、数据变了自动重算——不需要装真 Excel；
- **右边是接口接管层**：工作簿运行中发出的每个接口调用都被平台截住。你可以为每个接口配置**入参匹配规则**和**出参**（正常数据 / 异常 / 延迟 / 超时），打包成**场景**一键切换；
- **底下是三条记录流**：场景流（环境怎么变的）、流量流（外部来了什么）、操作流（用户做了什么）——因果关联成统一时间线，可回放、可回归。

一句话：**给"依赖接口取数的表格"一个可编程的数据环境**——相当于 Apifox/Mock.js 之于前端，但 mock 结果直接驱动一张会重算的表。

适用对象：报表/模板开发（验证数据变化时计算是否正确）、测试（不依赖真实后端构造边界与异常数据）、售前演示（同一张表演示不同数据效果）、前后端联调。

非目标（一期）：VBA/xll 宏执行、Excel 行为 100% 复刻（以自研引擎能力为边界）。

## 2. 核心概念

| 概念 | 是什么 | M1 |
|---|---|---|
| 接口 Interface | 被接管的一次外部调用：方法、URL 模式（支持 `{param}` 路径参数）、兜底策略 | ✅ |
| 规则 Rule | 接口下一条「入参→出参」映射：匹配器 + 响应 + 故障 + 优先级 | ✅（脚本出参/延迟类注入未做） |
| 场景 Scenario | 一组接口/规则的启用组合（interfaceId → ruleId） | ✅ |
| 流量 Traffic | 每次实际调用的记录：入参、命中规则、出参、causedBy | ✅ |
| 操作 Operation | 用户在表里做的每一步（进 undo 栈的命令），变更级 | ✅（交互级未做） |
| 项目 Project | 工作簿 + 接口 + 规则 + 场景 + 记录，整体可导出分享 | 部分（代码内定义，未做文件化） |

## 3. 总体架构

```
┌────────────────────────────────────────────────────┐
│ 控制台 UI（接口 / 场景 / 统一时间线）                  │
├────────────────────────────────────────────────────┤
│ 场景与规则引擎（匹配、优先级、模板渲染）                │
├───────────────────────┬────────────────────────────┤
│ 接口接管层（三通道）     │ Excel 运行时（web-spreadsheet）│
│ ① 函数桥（进程内）✅    │  工作簿打开/编辑、公式重算       │
│ ② Service Worker      │  API.* 自定义函数（溢出支持）    │
│ ③ 本地反向代理（进阶）  │  命令总线 → 操作记录            │
├───────────────────────┴────────────────────────────┤
│ 三条记录流：operations / traffic / scenarios（统一 seq） │
└────────────────────────────────────────────────────┘
```

最重要的架构决定：**接管层是运行时唯一的数据出入口**。工作簿不知道背后是真实接口还是 mock，业务模板零改动——这是"接管"的核心语义。

三条接管通道，按需组合，共享同一个规则引擎和记录流：

1. **函数桥（✅ M1 已实现）**：向公式引擎注册 `API.GET` / `API.POST` / `API.DATA` 取数函数，调用全部进规则引擎。最可控，天然拿到调用上下文，"单元格⇄接口"依赖图谱的基础。M1 全部走 mock（同步求值）；真实网络直通是 M3 代理通道的职责。
2. **Service Worker 拦截 fetch（零侵入）**：存量模板里写死的请求不用改。未实现。
3. **本地反向代理（进阶）**：平台起本地网关，客户端把 base URL 指过来即可——能接管真 Excel/WPS/任何浏览器外程序。未实现。

## 4. 规则引擎（平台的心脏）

### 4.1 一次调用的生命周期

```
重算触发 API.* 函数 → 函数桥进 MockHub → 定位接口（method + URL 模式）
 → 规则选择（场景钦定优先 → 优先级扫描，均需匹配器命中）
  ├─ 命中   → 渲染出参（static/template）→ 注入故障 → 返回 → 记流量（挂 causedBy）
  └─ 未命中 → 兜底策略（error → #API! / empty → 空）→ 记流量
→ 结果写回单元格 → 依赖单元格重算
```

### 4.2 入参侧：匹配 + 断言（✅ 均已实现）

- **匹配器**：query 参数精确匹配、`'*'` 通配。URL 路径参数（`{id}`）被提取供模板引用。规则全部匹配器命中才算匹配。
- **规则选择次序**：场景钦定的规则优先（场景是"这个接口用哪条规则"的显式选择）；钦定规则不匹配入参时回退到按优先级扫描其余启用规则——这是同一接口按不同入参分化出参的通道。
- **入参断言（✅）**：接口级 `assertions`（equals 精确 / oneOf 枚举 / 只查存在），**不影响规则选择与出参**，只校验"表格发出来的入参是否正确"，违规记入流量并在时间线标红（`⚠ 断言 region=east，期望 ∈ [north | south]`）。让平台从"喂数据"升级为"验行为"。

### 4.3 出参侧：响应能力（✅ static/template/script/capture 全部实现）

1. **static**：body 原样返回——二维数组出参经 `API.DATA` 转为动态数组直接溢出成表。
2. **template**：body 深遍历渲染 <span v-pre>`{{query.x}}`</span> / <span v-pre>`{{path.x}}`</span> 占位符——出参随入参动。整串占位符保留原始类型（数字还是数字）。
3. **script（✅）**：body 是一段 JS，签名 `(req) => body`（req = `{ query, path }`），返回值即出参——覆盖签名、分页、关联计算等动态逻辑。隔离级别（M2 有意取舍）：`new Function` + strict，异常捕获转 `#API!` 并记违规；仍在主线程，团队部署前须换 Web Worker / QuickJS 真隔离（依赖 M3 异步求值）。
4. **capture（✅）**：返回该接口最近一次真实捕获的快照（见 §M1.5 真实上游直通）。

### 4.4 故障注入（✅ 三态 + 概率 + 逻辑延迟全部实现）

- **`fault: 'error' | 'timeout' | 'none'`**：触发时返回 `#API!`；error 与 timeout 在流量里区分标注（同步求值下两者单元格效果相同，语义留给回放对账）。
- **`faultProbability`（0~1）**：按概率触发。种子是 `规则id#第N次命中` 的 FNV-1a 稳定摘要——**回放时命中序列重建，概率结果可复现**。
- **`delayMs`（逻辑延迟）**：记入流量的逻辑时间（时间线显示 `⏱300ms`），不阻塞同步求值；回放按逻辑时间对账。真实阻塞延迟依赖 M3 异步求值。

## 5. 场景

场景 = 每个接口在该场景下启用的规则。切换场景时：

1. 记录场景事件（场景流）；
2. **在因果窗口内**同步触发宿主回调——宿主调用 `FormulaEngine.recalculateAll()` 全量重算；
3. 重算中所有 `API.*` 调用按新规则出参，流量记录挂上场景事件的 causedBy。

`recalculateAll` 按公式依赖图的 Kahn 拓扑序重算，保证上游先写、下游读到的是新值（注册顺序与依赖方向相反也正确）。

**一次点击，整张表换一个世界。**

规划：断言（回归用例）——场景应用后检查指定单元格的值/错误类型，`场景 + 断言集` 接 CI（headless 跑运行时，复用现有 Playwright 基建）。

## 6. 操作记录子系统

### 6.1 采集（✅ 已实现，变更级 + 值采样）

**挂钩点**：命令总线的 `command:executing` / `command:undoing` / `command:redoing` 前置事件（本次为平台新增，镜像既有的 executed/undone/redone）。所有进 undo 栈的变更（编辑、插入删除行列、排序、粘贴、格式……）都经过命令总线，天然去重、天然结构化——不需要在几十个 UI 入口埋点。

记录内容：`{seq, ts, kind: 'op', type: 命令名, via: user|undo|redo, target, before, after}`。undo/redo 本身也是一等操作。

**值采样（✅）**：命令执行前/后各采一次目标位置的当前值（`opDetail.sampleOp`），补进操作记录——时间线能直接回答"**改了哪里、从什么值变成什么值**"：
- 单元格命令（编辑/恢复）：`target=B3`，公式单元格显示公式本体，空单元格显示 ∅；
- 行/列结构操作：`target=第5-6行`（无值）；
- 区间命令（样式/填充/边框）：`target=B2:D5`（无值）；
- 未识别命令：只显示命令名。

完成事件按命令实例配对（executing/executed 携带同一 cmd），撤销方向自动相反。

记录分档（控制噪声）：变更级（默认，✅）→ 交互级（+ 选区/按键路径，规划，用于复现输入类 bug）→ 关闭（对外演示）。

### 6.2 因果链（✅ 已实现）

命令开始前 `openCause` 埋锚点（seq），窗口内重算触发的所有接口调用挂 `causedBy: opSeq`；命令完成后关窗。时间线上每条流量都能回答"**谁引发的这次调用**"，反向也可（一次操作波及哪些接口、哪些单元格）。

已知限制：嵌套命令会提前关窗（M1 记录于此）。

### 6.3 回放与复现包（✅ 回放引擎与复现包已实现）

- **回放引擎（`src/platform/replay.ts`）**：按 seq 重演时间线里的场景切换与可重放操作。操作记录带**可重放载荷**（`ReplayPayload`：setCell 含坐标与文本，insertRow/deleteRow/insertCol/deleteCol 含位置与数量），由 `opDetail.sampleOp` 在记录时从命令 args 提取。命令直接对 store 重建执行（不污染 undo 栈），回放过程以 `via='replay'` 入时间线、接口调用挂其因果；**每步与记录的 after 值比对**，偏差（期望 vs 实际）逐条上报——回放即自带断言。回放起点快照时间线，自身事件不会被重复回放。
- **复现包（`src/platform/bundle.ts`）**：`工作簿快照(store.serialize) + 项目 + 捕获 + 事件流` 一个 JSON 文件（`.repro.json`），导入即整体替换（undo 栈随之清空），再点回放即可确定性复现。解决"我这里好好的"。
- **规划中**：回放控制条（步进/断点/到第 N 步）、`场景 + 操作序列 + 断言集` 形式化回归用例接 CI、流量入包。

## 12. 风险与开放问题

1. **异步函数 × 重算风暴**：真实网络直通后，接口函数是重算图里的慢节点，需要请求去重、防抖、循环依赖防护。
2. **沙箱安全**：团队部署时规则脚本就是用户输入，服务端必须真隔离。
3. **直通真实度**：鉴权、签名、Cookie 在直通与 mock 之间的语义一致性。
4. **`#API!` 不在 `EXCEL_ERRORS` 集合内**：ISERROR/IFERROR 不识别它（M1 有意为之——错误标记保持可读文本；正式化时应注册平台错误并纳入错误传播）。
5. **嵌套命令的因果窗口**：内层命令的 executed 会提前关窗（M1 已知限制，M2 引入因果栈）。
6. **方向问题**（设计期遗留）：若目标从"表格自定义函数调的 HTTP 接口"变为"真 Excel 插件（Office.js/VBA）调用的接口"，浏览器运行时覆盖不了——本地代理通道需提前，且运行时退化为宿主模拟，基本是另一个产品。
